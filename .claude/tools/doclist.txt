# doclist.txt -- the package list for doccmp.sh (#227/#760).
#
# WHY THIS IS NOT JUST pkglist.txt. doccmp compares the port's checker STATE against the oracle's
# `odin doc` output, so it can only measure packages the ORACLE can document. Running it over all
# 323 packages in pkglist.txt gives 300 STATE-MATCH and 22 non-results, and the 22 are NOT a signal
# about the port -- they are packages where there is nothing to compare, or where `odin doc` itself
# fails on this target. Feeding them in makes the gate permanently red and therefore useless (#215:
# a gate that always fails gets deleted).
#
# THE 22 SPLIT INTO TWO KINDS, and #760 made doccmp report them differently because they ARE
# different. Measured, not assumed -- `odin doc <pkg>; echo $?` on each:
#
#   A. rc=0, nothing exported (7). The oracle ran fine and documented no declarations.
#      core/odin                  a doc.odin-only aggregator package -- one file, no declarations
#      core/rexcode               same shape
#      core/simd/arm              `package simd_arm`, all contents #+build-gated away on amd64
#      core/sys/kqueue            platform-gated, nothing survives on linux
#      core/sys/wasm/wasi         platform-gated
#      vendor/windows/GameInput   platform-gated
#      vendor/windows/XAudio2     platform-gated
#
#   B. rc!=0, THE ORACLE FAILED (15). `odin doc` emitted errors and documented nothing. These are
#      not port results in either direction; the reference could not check them here.
#      core/sys/darwin            3 errors: `Undeclared name: system` / `RUsage` -- darwin-only
#                                 names, not declared when checked on linux/amd64
#      core/sys/freebsd           31 errors, same class
#      core/path                  1 error
#      core/odin/format           1 error
#      core/odin/printer          1 error
#      core/rexcode/isa/arm32/tools      \
#      core/rexcode/isa/arm64/tools       |
#      core/rexcode/isa/mips/tools        |
#      core/rexcode/isa/mos6502/tools     |  each is a DIRECTORY OF STANDALONE `package main`
#      core/rexcode/isa/mos65816/tools    |  GENERATOR PROGRAMS, so every one of them fails with
#      core/rexcode/isa/ppc/tools         |  `Redeclaration of 'main' in this scope`. That is
#      core/rexcode/isa/ppc_vle/tools     |  correct behaviour from the oracle on a directory that
#      core/rexcode/isa/riscv/tools       |  is not a single coherent package.
#      core/rexcode/isa/rsp/tools         |
#      core/rexcode/isa/x86/tools        /
#
# NOTE the two `tools` packages that are NOT excluded -- core/crypto/_edwards25519/tools and
# core/crypto/_weierstrass/tools BOTH document cleanly and are MEASURED. Until #760, doccmp printed
# only the BASENAME, so all twelve `tools` packages produced the identical label `tools` and this
# 10-vs-2 split was invisible. That is why the exclusions here are full paths.
#
# base/runtime is DELIBERATELY KEPT: `odin doc base/runtime` emits nothing (rc=0), and doccmp has a
# named DOC-EMPTY-EXPECTED arm for exactly that one package. It is a measured, explained result.
#
# REGENERATE by re-running doccmp over pkglist.txt and re-partitioning by `odin doc` rc. An entry
# that starts documenting cleanly should be PROMOTED back (#748: exclusions decay in both
# directions), and the way to notice is that this file names each exclusion's reason so a stale one
# can be checked.
