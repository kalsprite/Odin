## Bug #1: Duplicate Vet_Flag_Bit Definition

**Status:** ✅ FIXED
**Severity:** High (Compilation Error)
**File:** `checker.odin`

### Problem

`Vet_Flag_Bit` enum was defined in two locations:
1. `checker.odin` lines 265-278
2. `build_settings.odin` lines 261-274

This caused a compilation error:
```
Error: Redeclaration of 'Vet_Flag_Bit' in this scope
```

### Root Cause

During the development of the checker, Vet flags were initially defined in `checker.odin`. Later, when `build_settings.odin` was properly ported, the same definitions were added there (which is the correct location according to the C++ codebase structure).

The duplicate in `checker.odin` was not removed, causing the conflict.

### Solution

Removed the duplicate definition from `checker.odin` and replaced it with a comment directing developers to the canonical location:

**Before** (`checker.odin:262-286`):
```odin
// Vet_Flag controls code quality checks and style enforcement
// C++ Reference: /mnt/c/odin/src/build_settings.cpp:299-318
Vet_Flag_Bit :: enum {
	Shadowing            = 0,
	Using_Stmt           = 1,
	// ... 12 enum values
}

Vet_Flags :: bit_set[Vet_Flag_Bit;u64]

VET_FLAG_UNUSED :: Vet_Flags{.Unused_Variables, .Unused_Imports}
// ... more constants
```

**After** (`checker.odin:262-263`):
```odin
// NOTE: Vet_Flag_Bit, Vet_Flags, and related constants are defined in build_settings.odin
// to avoid duplication. See build_settings.odin:261-286
```

### Verification

✅ Compilation error resolved
✅ `build_settings.odin` contains complete implementation
✅ All Vet flag functionality preserved
✅ No functional changes

### Files Modified

- `checker.odin` (lines 262-286) - Removed duplicate, added redirect comment

### Files Unchanged

- `build_settings.odin` - Contains canonical definition (correct location)

## Lessons Learned

### Why This Happened
1. Incremental porting from C++ to Odin
2. Multiple development sessions over time
3. `build_settings.odin` added later in development
4. Duplicate not caught during initial implementation

### Prevention
1. **Grep for duplicates** before adding new type definitions
2. **Reference canonical locations** in comments
3. **Regular build verification** to catch compilation errors early
4. **Code review** to spot duplications

### Best Practices Going Forward
1. Check for existing definitions before adding new ones
2. Use comments to redirect to canonical locations
3. Keep build_settings types in `build_settings.odin`
4. Keep checker core types in `checker.odin`
5. Document module responsibility boundaries
