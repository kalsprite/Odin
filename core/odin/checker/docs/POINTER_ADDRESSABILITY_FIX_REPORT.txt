POINTER ADDRESSABILITY FIX REPORT
==================================
Date: 2025-10-02
Task: Fix pointer addressability errors in switch statements (9 original locations + 3 additional)

PROBLEM SUMMARY
---------------
Odin switch statements over Exact_Value unions cannot take addresses of variant bindings directly.
The pattern `#partial switch val in v { case big.Int: f(&val) }` fails because `val` is a copy, not addressable.

ROOT CAUSE
----------
In Odin, when you switch over a union type with a binding variable, the bound variable is a VALUE COPY of the variant, not a reference to it. Therefore, you cannot take its address directly with `&val`.

SOLUTION PATTERN
----------------
The correct pattern for getting a pointer to a union variant in a switch statement is:

```odin
#partial switch _ in v {  // No binding variable
case big.Int:
    temp := v.(big.Int)     // Extract the value into a temporary
    ptr := &temp            // Take address of temporary
    f(ptr)                  // Use the pointer
}
```

Or in compact form:
```odin
#partial switch _ in v {
case big.Int:
    temp := v.(big.Int); f(&temp)
}
```

KEY LEARNINGS
-------------
1. Odin union switch bindings create VALUE COPIES, not references
2. To get a pointer to a union variant, must:
   - Extract the variant into a temporary variable
   - Take the address of that temporary
3. The pattern `#partial switch &val in v` is NOT valid syntax in Odin
4. Always use `#partial switch _ in v` (with underscore) for unnamed switches
